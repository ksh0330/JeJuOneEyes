# 대회 기획서와 최종 ZIP 준비

제출 요구사항과 산출물 계획을 정리한 문서다. [공식 대회 안내](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)는 제주데이터허브 또는 제주빅데이터센터 데이터 1종 이상의 실질적 활용, 15쪽 이내 기획서, 실행 가능한 최종 ZIP을 요구한다. 기획서와 ZIP의 공지상 마감은 **2026년 11월 20일 오전 10시 KST**다. 기획서가 상호평가에 공개되므로 공개 가능한 화면과 근거만 사용한다.

## 기획서 15쪽 구성

| 쪽 | 내용 | 준비할 근거 |
| --- | --- | --- |
| 1 | 제안 요약 | 센터에 들고 오는 질문과 확인 가능한 결과 |
| 2 | 현장 사용자와 업무 | 상인·도민·도내 기업·공공 실무자 사례 |
| 3 | 분석이 막히는 과정 | 자료 선택, 지역·기간 단위, 지표 혼동 |
| 4 | 센터 방문자 이용 흐름 | 질문 입력부터 근거 확인, 후속 질문까지 |
| 5 | 세 입력 방식과 FAQ | 자연어, 체크박스·라디오, 예시 질문의 실제 시작 화면 |
| 6 | Agent 구조와 도구 호출 | 질문 해석, 계획 JSON, KG, 로컬 분석 엔진 |
| 7 | 데이터 출처·이용조건 | 실제 사용 파일과 기간, 센터 확장 대상 |
| 8 | 전처리·EDA와 집계 기준 | 카드 금액과 방문인구의 집계 단위, 반복 값 처리 |
| 9 | 첫 질문 실행 | 2019년 연동·노형동 비교 표와 차트 또는 실제 구현이 제공하는 결과 형식 |
| 10 | 후속 질문과 조건 변경 | 7~8월 제외 전후, 이전 조건이 유지된 실행 화면 |
| 11 | 자료 범위와 오류 안내 | 미관측 월, 미지원 지표, 미검증 연결의 처리 사례 |
| 12 | 검증과 재현 | 검산 값, 실제 테스트 결과, 실행 환경과 명령 |
| 13 | 센터 PC 탑재 | Windows 기준 사양, 로컬 모델, 설치 방식과 측정 상태 |
| 14 | 도입과 공공 활용 확장 | 센터 자료 연결 절차, 공공 운영점검의 필요 데이터 |
| 15 | 제출물과 사용 안내 | 최종 ZIP 구성, 실행 진입점, 사용 모델·AI 활용 범위, 확인된 제약 |

한 가지 대표 시연을 끝까지 재현하는 것을 먼저 확보한다. 공공 운영 사례는 실자료로 실행되면 두 번째 시연으로 넣고, 자료가 확보되기 전에는 도입 계획에 기록한다. Gemini나 Claude에 문서 초안을 맡길 때는 공개 가능한 글·화면·집계 결과를 전달한다. 원자료, 실제 키와 내부 로그를 프롬프트 입력에 포함하지 않는다.

화면 캡처는 실제 실행이 준비된 뒤 팀원의 Claude Code 또는 Codex로 진행할 수 있다. 대표 질문, 결과와 근거, 후속 질문 변경 결과를 같은 커밋에서 캡처한다. 화면별로 커밋, 사용 데이터 연도, 분석 조건을 남긴 뒤 Gemini 또는 Claude 초안에 연결한다. 관측하지 않은 동작은 설계 또는 도입 계획으로 표시한다.

## ZIP에 연결할 산출물

| 공식 항목 | 구현 후 준비할 파일 | 포함할 내용 |
| --- | --- | --- |
| 실행 소스 코드 | `app/`, `core/`, `contracts/`, 제출용 의존성 목록 | 실행 코드, 제품 프롬프트, 도구·자료 연결, 모델 정보 |
| 실행환경·매뉴얼 | `README.md`, `docs/MANUAL.md`, 필요한 경우 `.env.example` | 데이터·모델 준비, 실행 명령, 입력 예시, 오류·제약, 외부 의존성 |
| 데이터 활용 명세 | `docs/DATA_SPEC.md` | 실제 사용 자료, 출처와 이용조건, 참고 자료, 집계 단위와 전처리, 외부 데이터·오픈소스 |
| 결과 설명자료 | `docs/RESULT_REPORT.md` | 문제 정의, 구현 및 실행 화면, 재현 방법, 검산, 한계, 센터 활용 계획 |

ZIP은 최종 검증을 마친 커밋에서 필요한 파일만 골라 로컬에서 만든다. 공개 CSV는 평가·실행자가 원출처에서 준비하도록 원래 파일명과 로컬 입력 방법을 문서에 적는다. 대회 첨부 파일, 센터 원자료, 실제 키는 로컬에서 관리한다. 정제 스키마도 출처와 공유 가능 범위를 확인하고 게시한다. 공개 저장소 또는 Private 저장소는 팀의 가시성 선택이며, 자료별 배포 제한은 저장소 가시성과 별개로 적용된다.

출시 전에 실행 환경 한 곳에서 ZIP을 풀고 대표 질문을 처음부터 다시 실행한다. 캡처에 사용한 데이터 버전·분석 조건·실제 수치와 기획서 설명을 대조하고, 사용 모델·AI 활용 범위·오픈소스·외부 의존성을 기록한다. 검증이나 구현이 남은 항목은 제출물에서 계획으로 표시한다.
