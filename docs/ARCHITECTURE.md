# JeJuOneEyes 공통 설계

JeJuOneEyes는 제주빅데이터센터 방문자를 위한 자연어 데이터 탐색·분석 Agent다. 상인과 기업 실무자는 시장조사에, 도민은 지역 현안 조사에, 공공 실무자는 자산 운영 점검에 같은 분석 흐름을 쓴다. 화면에서 업무를 선택하면 질문과 지표 선택을 돕는 예시를 보여준다.

## 제출 MVP 범위

허브의 [상권분석 매쉬업](https://jejudatahub.net/data/view/data/748) 중 확인된 2019년 공개 CSV로 `지역·월·지표 비교 → EDA 근거 → 7~8월 제외 후 재계산`을 완성한다. 앱에서 시연 자료의 실제 연도와 출처를 표시한다. 공개 파일은 이미 결합된 데이터라 실제 센터 원자료의 조인 경로는 별도로 검증한다. 음식물쓰레기 설비 운영은 기존 스키마 후보를 활용해 실제 이용 가능한 파일과 지표 단위가 확인되면 같은 엔진에 연결한다.

제주관광공사 공개 XLSX는 제주 전체의 입도객 확정치 전년 동월 비교에 한해 연결한다. 실행 시 [카탈로그](../core/kg/catalog.json)에서 질문의 지표에 맞는 자료를 선택한다. 두 자료의 결합 요청에는 지역 체계, 시간 단위, 공통 관측 기간, 검증 조인 관계를 조회한 사유를 표시한다. [데이터 활용 명세](DATA_SPEC.md)

## 모듈 경계

`자연어 / 선택지 / 예시 → 분석 계획 → 데이터·지표 선택 → 전처리·EDA·집계 → 결과·근거 → 조건 수정`

| 경로 | 책임 | 의존성 |
| --- | --- | --- |
| `app/` | Streamlit 초기 후보. 자연어, 라디오·체크박스, 예시 질문과 FAQ. 분석 조건과 변경 이력, 표·차트·근거를 렌더링한다. | 공통 분석 계획과 결과 계약 |
| `core/planner/` | 질문과 직전 계획을 읽어 구조화한다. 필요한 조건만 묻는다. 답변 불능, 모델 오류 시 선택지 입력으로 이어간다. 제품 프롬프트는 `core/planner/prompts/`에 버전 관리한다. | 계획 계약, 안전한 카탈로그 요약, 로컬 모델 |
| `core/kg/` | 등록된 데이터셋·지표·지역/시간 단위 검색과 매핑, 연결 후보의 상태 확인. | 카탈로그 계약과 사용이 허용된 정제 메타데이터 |
| `core/connectors/` | 공개 로컬 파일과 센터 지정 폴더에 제공된 CSV·Parquet의 읽기 전용 연결. 컬럼, 타입, 실제 범위 확인. 공개 파일 다운로드는 설치·준비 단계 명령으로 제공할 수 있다. | 로컬 데이터 경로, 등록 어댑터 |
| `core/analyzer/` | Python·DuckDB 초기 후보. 계획 및 실제 스키마 검사, 결측·중복 진단, 집계, 조인 검증, 결과와 근거 생성. | 계획·결과 계약, KG, 연결기 |

UI와 데이터 로더는 분석 계획 및 결과 계약을 사용한다. 제출 MVP에는 규칙 기반 플래너와 로컬 분석 엔진을 사용한다. Qwen2.5 0.5B Q4의 CPU 시험은 질문의 의도와 조건 추출로 한정하며, 사용 여부는 응답 시간과 정확도 측정 뒤 결정한다. Claude·Codex·Gemini는 개발 및 기획서 작성 도구다. [제출 준비](SUBMISSION_PLAN.md)

## JSON 계약 v1

| 파일 | 생산자 → 소비자 | 규칙 |
| --- | --- | --- |
| [분석 계획](../contracts/analysis-plan.schema.json) | 선택지 UI / 자연어 플래너 → 분석 엔진 | 내부 의미 ID, 월 기간, 지역, 선택 지표, 그룹·제외 조건. 사용자 문구를 실제 컬럼명·파일명·SQL로 사용하지 않는다. |
| [카탈로그](../contracts/catalog.schema.json) | 데이터 연결 담당 → 검색기·분석 엔진 | 자료 출처와 어댑터, 지역·시간 단위, 지표별 집계 기준, 알려진 조인 관계와 검증 근거를 관리한다. |
| [분석 결과](../contracts/analysis-result.schema.json) | 분석 엔진 → UI / 요약 | 표 데이터와 컬럼 단위, 실제 관측 월, 출처, 품질 및 한계 알림을 전달한다. |

- 시작·종료 월은 양끝을 포함한다. `exclude_months`는 기간 안에서 제외할 달 번호다. 결과의 기간은 실제로 관측·사용된 달로 기록한다. 날짜 역전, 모두 제외된 기간, 잘못된 ID는 실행 전에 설명한다.
- 후속 질문은 기존 계획을 복사한 뒤 명시적으로 바꾼 필드만 수정하고 전체 계획을 다시 검증한다. 모델 응답이 계약에 맞지 않으면 보정은 한 번만 시도하고, 실패하면 기존 조건을 보존한 선택지 또는 확인 요청을 보여준다.
- 카탈로그의 지표·컬럼 ID는 등록된 자료로 해석한다. 조인은 확인된 매핑, 공통 기간, 실제 키 유일성과 매칭률을 모두 확인한다. `candidate` 연결은 탐색에 쓰고 실행 시에는 검증 근거가 있는 `verified` 연결만 후보로 삼는다. `bjd`와 `emd_cd`의 이름이나 자릿수만으로 동일 지역을 가정하지 않는다.
- 측정값의 집계 단위를 따로 적용한다. 공개 매쉬업의 카드 금액은 대상 업종 행을 합산하고, 방문인구는 같은 지역·월·성별에서 반복되는 값이 일치하는지 확인해 한 번 반영한다. 업종 선택과 무관하게 방문인구는 지역 전체 지표로 표시한다. 방문인구 값이 충돌하면 해당 그룹과 영향을 표시한다. 누락과 관측값 0을 구별하고, 방문인구 월 누적치를 고유 방문자 수로 해석하지 않는다.
- 결과의 `columns`에 표시할 필드와 단위를 정의하고 `rows`는 해당 ID만 가진다. 누락 값은 `null`로 넘긴다. `needs_input`, `no_data`, `unavailable`, `error`에는 사용자용 사유를 제공하고 결과 행을 비운다. 일부 관측월을 제외하고도 유효한 비교를 만들면 `ok`와 품질 알림을 함께 반환한다. 실제 기간 겹침·조인·집계에 대한 검증은 JSON 형식 검사에 더해 실행 시 처리한다.

[분석 계획 예시](../contracts/examples/analysis-plan.json)와 [결과 예시](../contracts/examples/analysis-result.json)는 모듈 연결용이다. 결과 예시의 카드 합계는 해당 공개 CSV를 별도로 집계한 기준값이다. 앱 실행 결과는 구현 후 따로 확보한다.
