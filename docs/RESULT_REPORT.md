# 제주한눈 결과 보고서

제주한눈(JeJuOneEyes)이 무엇을 풀고, 어떻게 동작하며, 실제 공개 자료로 어떤 결과를 냈는지 정리한 결과 설명자료다. 수치는 모두 공개 원본 파일을 로컬에서 집계한 값이며 [최종 실행 확인](FINAL_CHECK.md)에서 다시 확인했다.

## 1. 문제 정의

제주빅데이터센터를 찾는 소상공인, 도민·연구자, 기업·공공기관 실무자는 업무 질문을 들고 오지만 어떤 자료를 어떤 단위로 집계해야 하는지 모른다. 같은 질문도 자료 선택, 지역·기간 단위, 지표의 집계 방식에 따라 숫자가 크게 달라진다.

- **자료 선택** · 자료 이름만으로는 어떤 지표·지역 단위·관측 기간을 담는지 알기 어렵다.
- **단위 차이** · 읍면동 자료와 제주 전체 자료, 2019년 자료와 2026년 자료를 그대로 붙이면 틀린 비교가 된다.
- **집계 방식** · 상권 매쉬업의 방문인구는 같은 지역·월·성별 값이 업종 행마다 반복된다. 연동 2019년 값을 단순 합산하면 6,320,043,946으로, 한 번만 반영한 186,786,305의 약 33.8배가 된다.

## 2. Agent 구조

| 단계 | 구성 요소 | 하는 일 |
| --- | --- | --- |
| 질문 해석 | `core/planner/` | 규칙과 어휘 사전으로 질문·선택지에서 목적, 지역, 기간, 업종, 지표, 제외 월을 뽑아 분석 계획 JSON을 만든다. 결과가 달라지는 조건이 빠지면 선택지로 되묻는다. 후속 질문은 직전 계획을 복사해 언급한 조건만 바꾼다. |
| 자료 조회 | `core/kg/catalog.json` | 지표에 맞는 자료와 지역 체계, 시간 단위, 관측 범위, 검증된 결합 관계를 찾는다. |
| 결합 판단 | `core/kg/catalog.py` | 두 자료가 걸린 요청은 지역 체계·시간 단위·공통 관측 기간·검증된 결합 관계를 확인한다. 하나라도 맞지 않으면 결합하지 않고 이유와 각 자료의 단독 분석을 제시한다. |
| 로컬 집계 | `core/connectors/`, `core/analyzer/` | 계획을 JSON Schema로 검증한 뒤 허용된 필터·합계·월별 추이·전년 동월 비교만 실행한다. 자유 형식 SQL·코드를 만들지 않으며 같은 조건이면 같은 값이 나온다. |
| 결과와 근거 | `app/` | 엔진 값으로 한 문장 답, 표, 그래프를 만들고 출처·실제 관측월·제외한 달·계산 방법·품질 알림을 함께 보여준다. |

제품은 언어 모델을 호출하지 않는다. 팀원 개인 PC에서 시험한 로컬 SLM(Qwen2.5-0.5B Q4)은 조건 추출 정확도가 낮아 연결하지 않았다([입도객·결합 요청 시연 기록](RECENT_ARRIVALS_DEMO.md)).

## 3. 주요 기능

| 기능 | 화면 |
| --- | --- |
| 세 가지 입력 | 퀵스타트 카드·업무별 예시 카드·자연어 입력·단계별 선택지(1 지역 → 2 기간·제외 월 → 3 지표). 같은 조건이면 같은 계획과 결과 |
| 한 문장 답 | 결과 맨 위. 예: "2026년 9월 제주 입도객은 112만 3,339명으로, 지난해 같은 달보다 5만 8,168명(4.92%) 줄었습니다." |
| 두 가지 보기 | 글로 보기(쉬운 설명·정확한 값·해석 한계·대표 그래프), 수치·그래프로 보기(대상별 값과 차이 카드, 차이 행이 있는 표, 값이 표시된 그래프). 전환해도 재분석하지 않음 |
| 근거 | 출처 링크·이용조건, 실제 관측월, 요청으로 제외한 달, 컬럼별 단위·계산 방법, 품질 알림, 계획·결과 원본 JSON |
| 후속 분석 | 제안 버튼, 화면 아래 고정 입력창, 바뀐 조건과 직전 결과 대비표, 변경 이력 |
| 최근 질문 | 사이드바에서 누르면 그때의 조건과 결과를 재계산 없이 다시 연다 |
| 자료 상태 | 상단 헤더의 연결 배지, 사이드바의 공개 자료·센터 원자료 상태. 파일이 없으면 파일명·공식 페이지·둘 위치를 안내 |

## 5. 검증 방법과 한계

- **검산** · 위 값은 공개 CSV·XLSX를 별도로 집계한 기준값과 대조했다.
- **자동 테스트** · `python -m unittest discover -s tests -p 'test_*.py'` 25건. 두 파일이 있으면 25건 통과, 파일이 없으면 실제 자료 테스트만 건너뛴다(둘 다 없음 4건, CSV만 없음 3건, XLSX만 없음 1건).
- **재현** · 최종 ZIP을 새 폴더에 풀어 문서대로 설치·실행했다. 결과는 [최종 실행 확인](FINAL_CHECK.md)에 있다.
- **한계** · 상권 분석은 2019년 연동·노형동, 한식 음식점업 또는 전체 업종 소계, 카드 이용금액·방문 유동인구로 한정한다. 결제 건수·건당 이용액은 계산하지 않는다. 입도객은 제주 전체 전년 동월 비교만 지원한다. 질문 해석은 규칙 기반이다. 센터 기준 PC(i7-8700, RAM 32GB)에서는 실측하지 않았다.

## 6. 센터 활용 방안

새 자료는 카탈로그 등록 → 스키마·단위 검사 → 결합 검증 → 분석 활성화 순서로 같은 흐름에 붙인다.

- **시장조사** · 센터 카드 이용(읍면동) 자료로 이용 건수와 건당 이용액을 나눠 본다. 카드 자료의 `bjd`와 유동인구 자료의 `emd_cd`는 매핑을 검증한 뒤에만 결합한다.
- **공공 운영 점검** · 음식물쓰레기 배출 현황(기준일, 설비 번호, 배출량)으로 주말 반복 고배출 설비와 누락일을 찾는다.
- **확장 범위** · 센터 예시 자료 70종은 스키마 등록 후보이며, 원자료 연결과 단위 검사를 마친 자료부터 분석을 연다.
